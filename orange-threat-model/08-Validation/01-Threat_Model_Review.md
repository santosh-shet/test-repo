# 01 – Threat Model Review

## Purpose

This document defines the review process for the threat model of the Orange Infrastructure Services supporting Tieto Banktech applications.

The objective is to ensure the threat model remains accurate, complete, and aligned with the current business, architecture, technology, and security landscape.

---

# Overview

Threat modelling is an iterative process.

The threat model should be reviewed whenever significant changes occur to the environment, architecture, infrastructure, or business requirements.

Periodic reviews also help ensure that identified threats, risks, and security controls remain relevant and effective.

---

# Review Objectives

The review should confirm that:

- The service scope remains accurate.
- The architecture reflects the current environment.
- Assets remain correctly identified.
- Trust boundaries remain valid.
- Data flows are still accurate.
- Threats remain relevant.
- Risks have been appropriately assessed.
- Security controls continue to mitigate identified risks.

---

# Review Triggers

The threat model should be reviewed when:

- New infrastructure components are introduced.
- Major architectural changes occur.
- New applications are deployed.
- Service scope changes.
- Significant security incidents occur.
- New third-party integrations are introduced.
- New regulatory or contractual requirements are identified.
- Significant vulnerabilities affecting the environment are discovered.

---

# Review Activities

Typical review activities include:

- Validate service scope.
- Review architecture diagrams.
- Review assets.
- Review trust boundaries.
- Review data flows.
- Review identified threats.
- Review risk ratings.
- Review security controls.
- Review residual risks.

---

# Review Participants

Threat model reviews may involve:

- Tieto Banktech Architects
- Security Architects
- Infrastructure Teams
- Orange Infrastructure Services
- Application Owners
- Risk Owners
- Security Operations

---

# Review Outcomes

The review may result in:

- No changes required.
- Updated architecture.
- Updated threat scenarios.
- New risks identified.
- Existing risks closed.
- Additional security controls.
- Updates to monitoring or validation activities.

---

# Review Frequency

Threat model reviews should be performed:

- Following significant architectural changes.
- Following major security incidents.
- Periodically as part of the organization's security governance process.
